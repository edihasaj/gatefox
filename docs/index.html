Set up your gateway ↓
Codex app→Gateway→Your models

The gateway adds models after your native model list. Your primary ChatGPT account stays signed in. Each added subscription has its own registration, and the computer that owns the workspace still executes tools and approvals.

The gateway translates API requests into provider requests and streams their responses back. It carries supported reasoning, text, tool calls, and images, and handles cancellation and provider errors. Your client chooses the models and agents, manages chats and permissions, and executes tools. The gateway does not assign agent roles or delegate work.

Desktop adapter in testing. The native connected-machine relay is tied to the tested Codex build. Check each device after an app update. See native transport requirements and verification status.

02 / GET STARTED

Install once on each Mac.

Already have a configured gateway? The Harness Gateway macOS app gives those settings a native control panel, with the fox in your Dock. It keeps the existing service running when you close its window.

The Apple Silicon installer includes its Node runtime. It needs no repository checkout or administrator access. You need GitHub access to the private release and the signed Codex desktop app.

Run these commands inside a new, empty download folder:

gh release download v0.4.1 -R edihasaj/harness-gateway \
  --pattern '*macos-arm64.tar.gz' --pattern SHA256SUMS
shasum -a 256 -c SHA256SUMS
tar -xzf harness-gateway-0.4.1-macos-arm64.tar.gz
./harness-gateway-0.4.1-macos-arm64/install
gateway --version

The installer keeps versioned releases under your user installation prefix. Upgrades preserve gateway registrations. They refuse an unrelated command named gateway.

Already using a development checkout?

Import its gateway-owned registrations into the installed data directory:

gateway setup --from-config /absolute/path/gateway.local.json

This refuses to overwrite an existing destination. Native Codex authentication and settings are not copied. Retire an obsolete local configuration after a successful migration; it can otherwise take precedence over the installed configuration.

03 / INFERENCE HOST

Connect your subscriptions.

Choose one Mac to run inference. Install the official Claude Code CLI there for Claude subscription use. The gateway registers the extra Codex account through its own Sign in with ChatGPT flow.

gateway init
gateway login claude
gateway login codex
gateway discover claude --load
gateway discover codex --load
gateway doctor
gateway service install
gateway desktop register

Complete each sign-in with the account you want that provider to use. For codex, choose your secondary account. The gateway keeps its Codex credentials in its own state directory. Claude uses the official CLI subscription login.

Native Codex settings, including an Obsidian-managed configuration, stay in place. No provider or billing fallback occurs when a request fails.

Adding Copilot or an API provider

Add a provider to the gateway JSON with a unique ID, label, adapter type, and model alias map. Copilot uses copilot-subscription; ordinary API adapters include responses-api and chat-completions-api. Read provider configuration before editing it. Copilot requires its native CLI subscription login and SDK protocol 3.

gateway login copilot
gateway discover copilot --load
gateway doctor
04 / DAILY USE

Pick a model. Start a chat.

After first registration, finish active work and quit the app normally once. Launch it with the installed command:

gateway desktop
gateway desktop status
  1. Start a new chat and select the computer and project where the work belongs.
  2. Open the model list. Added models have labels such as Claude · Opus 5.5 and Codex 2 · GPT-6.1-Sol.
  3. Choose a supported reasoning level, then send your task.

The app owns chat naming. The gateway forwards title reads, renames, and live updates through the client's native protocol; it adds no naming tool or instructions.

What to expect in a gateway chat
ControlBehavior
Files and instructionsThe native executor reads the selected project's AGENTS.md and executes tools in that workspace.
Follow-ups and model changesHistory carries through supported gateway model changes. Start a new chat to cross between a loaded native account and the gateway provider.
ImagesClaude and Codex 2 accept supported image attachments. The current Qwen route accepts text only.
Stop and resumeStop cancels the active request. Resume by sending another turn or reopening the saved chat. There is no provider-level pause that freezes inference.
Access and steeringThe native executor owns permissions and approvals. The router carries native steering and goal messages; remaining rendered checks are tracked separately.

The backend advertises supported reasoning efforts. Enable Max or Ultra under Model features in the app that renders the picker. The gateway saves supported display changes privately so they survive restart. The circular arrow is Reset to default: it selects a default model and effort. Reopen the picker to request current model metadata; the app can cache that request.

Standard is the default speed. Fast is selectable only where the provider advertises it, independently of reasoning. Codex 2 discovery carries the account's speed options across local and connected machines; your original account keeps its own controls. The current Copilot CLI offers no Fast tier for a selected model. Updated adapter code takes effect at the next normal launch; installing it preserves current chats.

05 / MODEL CATALOG

Load the models your account offers.

Discovery reads the provider's current catalog. With --load, it saves those routes. Omit --select to load every offered model; use it to keep a smaller list.

gateway discover claude --load
gateway discover codex --load
gateway catalog

For the four-model Copilot selection used in this setup:

gateway discover copilot \
  --select gpt-6.1-sol,gpt-5.6-terra,claude-sonnet-5,claude-opus-5.5 --load

These IDs must exist in your account's discovery result. Repeat discovery without --load to inspect newer offerings. An unrestricted load replaces the selection with the full offered list.

The provider's label sets the name before the middle dot. Providers follow configuration order; model metadata priority controls order within a provider. There is no recent-use sorter.

Saved routes reload on the next inference request. Desktop adapters fetch current metadata when the app requests its catalog; a picker already open may need to close and reopen. The optional CLI uses a startup snapshot.

06 / SHARED CATALOG

One host. The same models on your Macs.

Keep provider registrations on the inference host. Each client needs the installed gateway and a private authenticated connection to that host. Transfer only the gateway client token through SSH:

umask 077
mkdir -p "$HOME/.local/state/subscription-gateway-client"
ssh user@inference-host 'gateway token' \
  > "$HOME/.local/state/subscription-gateway-client/client-token"
gateway setup --client --port 3459 \
  --token-file "$HOME/.local/state/subscription-gateway-client/client-token"
gateway tunnel install --tunnel-id host --host user@inference-host \
  --port 3459 --remote-port 3457
gateway doctor
gateway desktop register

The client token grants access to all configured gateway accounts. Keep it owner-only and give it only to trusted devices. Provider credentials stay on the host; workspace files stay on the execution computer.

Use an existing Control other devices connection

The experimental native relay reuses that machine's existing registration. It adds no separate computer or SSH entry in the app. Install a release with the matching relay, finish local and remote work, then quit ChatGPT normally on that machine before activation.

gateway native install
gateway desktop register
gateway desktop
gateway native status

If a managed native relay already exists, use the service consolidation procedure below to replace an older test path. Keep working SSH connections until the original native connection passes its real desktop checks. Read the SDK and account requirements.

Each execution backend must be registered. A synced chat alone cannot make an unconfigured machine recognize subscription_gateway.

07 / OPERATIONS

Keep one managed service.

The daemon must be up for gateway inference. A macOS user LaunchAgent starts it at login and restarts it after a crash. The supervisor retries failed components without replacing healthy ones. The inference host must stay awake and reachable.

gateway service status
gateway native status
gateway doctor

Preview consolidating gateway jobs. Apply only after local and remote chats finish and ChatGPT is closed on that machine:

gateway service consolidate
gateway service consolidate --apply

One supervisor owns inference, required SSH tunnels, the native relay, and login setup. Provider CLIs and chat executors still run as children. Consolidation saves rollback copies and excludes unrelated jobs, including the GitHub Actions runner.

Restart also requires a maintenance window. Uninstall stops owned components and moves installed files to Trash; it preserves credentials and native configuration.

gateway service restart
# Remove the gateway installation when you intend to stop using it:
gateway uninstall

See service ownership and rollback and upgrade checks. A crash restart does not promise that an interrupted turn completes automatically.

09 / OPTIONAL

Use a separate Codex CLI home.

gateway codex-config generates a complete configuration, not a named profile. Save it in a separate home to preserve your primary settings:

gateway_cli_home="$HOME/.local/state/subscription-gateway-cli"
mkdir -p "$gateway_cli_home"
gateway codex-config --model codex/gpt-6.1-sol \
  > "$gateway_cli_home/config.toml"
CODEX_HOME="$gateway_cli_home" codex

This CLI home has its own history and settings. It does not inherit all native customizations. Regenerate the snapshot after changing the gateway's model selection.
